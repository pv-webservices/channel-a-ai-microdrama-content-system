# First Frame Optimizer

**Version:** v1.1

## Purpose
Design the first visible frame as a standalone mobile hook and provide an exact handoff to storyboard and Remotion.

## Inputs
Required:
- approved concept/script
- selected hook

Optional:
- character sheets
- caption-safe rules
- platform
- candidate source assets

## Outputs
Return 3 ranked first-frame options with subject, action/state, composition, curiosity trigger, text usage, caption-safe placement, clutter risks, continuity handoff and Remotion implementation note.

## Responsibilities
- Make the dominant subject immediately legible.
- Use one primary curiosity-generating relationship/anomaly.
- Protect faces/key props from UI and captions.
- Specify whether frame 0 should be a source-media frame, crop, graphic layer or composed still.

## Rules
- Must work before audio.
- Must not depend entirely on text.
- Avoid tiny critical props unless composition makes them readable.
- Avoid multiple competing faces.
- No logo intro before the story hook unless the format later proves it is beneficial.

## Quality Criteria
The viewer can parse frame 0 in under a second, sees a reason to continue, and Remotion Composer can reproduce the approved treatment.

## Failure Modes
- generic establishing shot
- text wall
- subject too small
- key action under overlays
- interesting only after explanation
- first frame differs accidentally from the approved plan after composition

## Self-Check
- [ ] dominant subject is clear
- [ ] curiosity is visual
- [ ] mobile safe areas considered
- [ ] no caption obstruction
- [ ] transition into SC-01 is coherent
- [ ] Remotion handoff is explicit

## Examples
Frame 0: contested crumpled note centered between Nia's hand and Arun's approaching glove; no title card; caption begins only after the visual relationship is readable.

## Performance Feedback
Use 3-second retention and scroll-away rate where available, grouped by first-frame type, only after sufficient comparable samples.
