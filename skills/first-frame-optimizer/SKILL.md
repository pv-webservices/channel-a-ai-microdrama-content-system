# First Frame Optimizer

**Version:** v1.0

## Purpose
Design the first visible frame as a standalone mobile hook before audio or motion begins.

## Inputs
Required:
- approved concept/script
- selected hook

Optional:
- character sheets
- caption-safe rules
- platform

## Outputs
Return 3 first-frame options, each with:
- Subject
- Action/state
- Composition
- Curiosity trigger
- Text usage
- Caption-safe placement
- Clutter risks
- Continuity handoff

Rank the options.

## Responsibilities
- Make the dominant subject immediately legible.
- Use one primary curiosity-generating relationship/anomaly.
- Protect faces and key props from UI/captions.

## Rules
- Must work before audio.
- Must not depend entirely on text.
- Avoid tiny critical props unless composition makes them readable.
- Avoid multiple competing faces.

## Quality Criteria
The viewer can parse the frame in under a second and sees a reason to continue.

## Failure Modes
- generic establishing shot
- text wall
- subject too small
- key action under overlays
- interesting only after explanation

## Self-Check
- [ ] dominant subject is clear
- [ ] curiosity is visual
- [ ] mobile safe areas considered
- [ ] no caption obstruction
- [ ] transition into shot 1 is coherent

## Examples
Close framing on a crumpled handwritten note held between a student's hand and a janitor's approaching glove, with the contested object dominant.

## Performance Feedback
Use 3-second retention and scroll-away rate where available, grouped by first-frame type, only after sufficient comparable samples.
