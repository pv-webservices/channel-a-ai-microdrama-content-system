# Contributing

## Rule of authority

Treat `PROJECT.md`, the relevant `SKILL.md`, and policy files in `docs/` as authoritative. Do not introduce providers, benchmarks, automation, or publishing behavior that conflicts with them.

## Skill changes

A Skill change must:
1. preserve its stage boundary,
2. retain the standard Skill sections,
3. update its documented version when behavior materially changes,
4. explain performance-driven changes using supporting analytics/experiment evidence,
5. avoid unrelated rewrites.

Do not change a Skill because of one anecdotal reaction or one outlier video.

## Production artifacts

Use IDs from `docs/naming-conventions.md`. Only move a video into approved/published state after required human review.

## Review checklist

Before merging:
- no real secrets,
- no fabricated performance values,
- no unlicensed copyrighted material,
- no fake real-person events,
- naming and IDs are consistent,
- changed docs are concise and actionable,
- no premature publishing automation.
