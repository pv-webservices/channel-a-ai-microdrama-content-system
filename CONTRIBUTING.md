# Contributing

## Rule of authority
Treat `PROJECT.md`, the relevant `SKILL.md`, and policy files in `docs/` as authoritative.

## Required engineering checks
Before merging code/configuration changes:

```bash
npm ci
npm run validate
```

GitHub Actions runs the same validation gate on pull requests and `main`.

Do not hand-author `package-lock.json`; it must be generated by npm from `package.json` and then committed.

## Skill changes
A Skill change must:
1. preserve its stage boundary,
2. retain all standard Skill sections,
3. update its documented version when behavior materially changes,
4. explain performance-driven changes with supporting evidence,
5. avoid unrelated rewrites.

Do not change a Skill because of one anecdotal reaction or one outlier video.

## Production artifacts
Use IDs from `docs/naming-conventions.md`. A historical/pre-Remotion result cannot satisfy a current Remotion Render Validation or QC gate.

## Review checklist
- no real secrets
- no fabricated performance values
- no unlicensed copyrighted material
- no fake real-person events
- naming/IDs consistent
- manifests validate
- TypeScript passes
- Remotion composition resolves
- no pending source asset represented as publish-ready
- no premature publishing automation
